### Tier 3 — Discuss before implementing (C9–C12)

Decision required before any code is written. Confirm param compatibility and architectural impact in a session, then move to active tasks.

- [x] **C9 — `glyphRender / glyphMotion / matrixRain` → `text`** — ✅ 2026-06-03 decided: **skip**. The three ops share only `mix`; glyphMotion uniquely requires `u_motion_tex` binding; glyphRender's existing `mode` param (ascii/binary/blocks/halftone) would create nested selectors. A merged op would carry ~20 params with almost no shared semantics — the C7/C8 pattern requires a genuine shared anchor param, which this set lacks.
- [x] **C10 — `pinchBulge / sinkSourceField` → `warp`** ✅ 2026-06-03 — mode selector [0=lens, 1=flow]; shared params: mix, strength [-1.5,1.5], radius, falloff, centerX, centerY, drift, advect; `spin` [-2,2] added (no-op at 0 in lens mode); `amount` renamed to `strength` to unify the two ranges; `ownedState` preserved; 1 op removed; 2 presets migrated (singularityBloom → mode=0 with strength=-0.22, fieldOrbitLab → mode=1 with spin=0.38); new `audit-warp-mode-sweep` QA case.
- [x] **C11 — `spiralField / vortex`** — ✅ 2026-06-03 decided: **skip**. The ops are algorithmically unrelated: spiralField is a single-center analytical rotation field (pure shader); vortex is a CPU-simulated sum-of-32-point-vortices using Biot-Savart interactions with non-trivial per-frame CPU state (`seedVortices`, `#advect()`). Shared params are only `mix`, `drift`, `advect` — the generic feedback trio shared by most ops, not a semantic anchor. A mode selector would expose 9+5 params with 6 dead in each mode, or silently break vortex's CPU simulation.
- [x] **C12 — `dataMosh / flowMosh`** — ✅ 2026-06-03 decided: **skip**. Only `mix` shares identical semantics. dataMosh needs an external motion field from the renderer (`resources.motionField`) and uses `ownedState` without `bindAsPrevFrame`; flowMosh owns two FBOs (`ownedState` with `bindAsPrevFrame` + `ownedState2` for LK reference) and computes its own optical flow from `u_prev_vid`. The `bindRendererResources` paths, state models, and param surfaces are incompatible — a unified op would require mode-keyed `bindRendererResources` logic with no net simplification.
